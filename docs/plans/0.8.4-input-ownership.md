# 0.8.4 roadmap 建议：Input Ownership 落地

> 状态：**建议，未开工**（2026-10-13）。契约本体见 [`../decisions/input-ownership.md`](../decisions/input-ownership.md)（AD-20）。
> 本文只规划，不含实现；每个工作项给出**现状 → 目标 → 成本/风险 → 验证 → 完成判据**。
> 顺序是硬的：W-1/W-2 是安全网与骨架，W-3 才是用户能感觉到的修复，W-4…W-6 是新功能。

**总原则**：先有测试表，再动实现；每一步都可独立发布；0.8.4 不引入新功能，只做 W-1…W-3。

## W-1 · Reader 抽取（**已完成 2026-10-13**，纯搬移，0 行为变化）

| 项 | 内容 |
|---|---|
| 现状 | 字节 → 文本 → 事件的全部状态散在 `tui.ts`：`decoder`、`inputGuard`、`escapeBuffer`/`escapeTimer`(60ms)、`inPaste`、`processPasteChunk`、`screenKeys`、`looksLikePasteBurst`、两处 SGR 解析；`picker.ts` 还有一份自己的 guard + escape 组装（G-6/G-9） |
| 目标 | `src/input-reader.ts`：`Reader.push(bytes) → InputEvent[]`。它拥有解码、回复剥离、持有窗口、粘贴标记、拆键；**只输出事件**，不读 `screen`/`dialog` |
| 成本 | 搬移 ~350 行 + 类型定义；`tui.ts` 从"读字节"退回"收事件" |
| 风险 | 中。持有窗口的顺序语义（60ms ESC / 30ms CPR 尾）必须逐字保留，否则分片粘贴、分片 CPR 会回退；`screenKeys` 的"可打印文本连成一段"规则不能变（否则 confirm 会被 `yes` 作答） |
| 验证 | W-0 的表全部**不改断言**跑绿；`tests/terminal-input.test.mjs` 原样通过；真机探针（setup/probe）通过 |
| 完成判据 | 无任何用户可见变化；`picker.ts` 至少改用共享 Reader 的结论（或明确记为 W-7 不做） |

**已执行**：`src/input-reader.ts`（AD-21）承接 decode / 回复过滤 / 转义组装 / 粘贴边界 / 单元分类；
`InputFrame` 六种 tag；`tui.ts` 的 `handleInputText` 变成 assemble → paste 帧 / `route()`。

M1/M2/M3 三个 mutation 全部实测会红。`picker.ts` 的独立 reader 记为 **W-7**（本轮不动）。

## W-2 · Router + 四个 owner adapter（**已完成 2026-10-13**，0 行为变化）

| 项 | 内容 |
|---|---|
| 现状 | 归属判定分散在 `handleInputText` 阶梯 2–14、`handleChar` 的 switch、`handleScreenInput`、`handleDialogChar`，每处各自读 `screen`/`dialog`（F-1 的温床） |
| 目标 | `src/input-router.ts`：`route(event, {hasScreen, screenKind, hasSurface, surfaceHasField}) → 'screen'|'surface'|'composer'|'workspace'`，纯函数、无状态；四个 adapter 实现 `InputOwner`（§4.4）；`handleChar` 的第二个 Screen 门（死代码）与 Ctrl+L 的第二份实现一并删除（G-6） |
| 成本 | ~250 行 + 调用点改写；`tui.ts` 净减行数 |
| 风险 | 中高（最热路径）。要求：`route` 对**单键**不分配对象（可打印字符走快路径），否则 `bench` 的 `setup-typing`/`stream-tick` 会退化——`npm run bench` 是本项的硬门（ms 抖动不看，只看"是否有整屏清屏/寻址行数暴涨"） |
| 验证 | W-0 全表 + `npm run bench` + `npm run freeze`（F 系列计数为 0）+ 三条真机探针 |
| 完成判据 | `tui.ts` 里 `this.screen !== undefined` / `this.dialog !== undefined` 只剩 Router 与 owner 白名单；`handleInputText` 缩成"Reader → Router → owner" |

**已执行**：`src/input-router.ts`（AD-22）+ 四个适配器；`ownerReads` 31/59 → **25/54**、`rawBranches` 13 → **8**、`mouseParsers` 2 → **1**、死 Screen 门 1 → **0**；72 条 fixture / 246 次边界调用与抽取前逐字节一致；四个 mutation 全部实测会红。详见 [`../decisions/input-router.md`](../decisions/input-router.md) 与契约 §10。

## W-3 · 合并 read 的修复（本版唯一用户可见变化）

| 项 | 内容 |
|---|---|
| 现状 | G-1 一次 read 多个键全丢（composer）；G-2/G-8 rebind 键同 read 失效；G-3 Alt 和弦 + 下一字符 → 文本泄漏；G-4 `0x16` 无处理；G-7 focus 靠巧合；G-10 **所有复制路径清空 composer 草稿** |
| 目标 | Reader 的拆键对**所有 owner** 生效（0.8.3 只在 Screen 生效）；keymap 查表按**单键**而非整段；Alt 分支消费自己的和弦；`CSI I/O` 显式吞掉并加注释；`0x16` 在 hint 里说明；**`copyPlainText` 不再清空草稿**（只有"`/copy` 是输入框里提交的那条命令"这一种情况由 Composer 自己清） |
| 成本 | ~140 行（多数在 Reader 与 keymap 查表；G-10 是删三行 + 一个条件） |
| 风险 | 中。`\x1b1x` 这类"Alt + 文本"的语义要和 xterm 对齐（Alt 作 Meta 前缀）；粘贴中的键**不能**被拆开（`inPaste` 优先于拆键） |
| 验证 | W-0 里先红的 4 条转绿；`tests/interaction-surface.test.mjs`/`setup-screen.test.mjs` 不回归；Windows 腿的真机探针（ConPTY 合并 read 更常见） |
| 完成判据 | G-1/2/3/8/10 用例绿；`/diag` 里 `unknown` 事件计数可用（可选） |

## W-4 · Completion migration（命令补全迁到 Surface）

| 项 | 内容 |
|---|---|
| 现状 | 补全住在 composer 路径里：`buildSuggestions`、`suggestionIndex`、Tab 接受、`suggestionsVisible()`；`↑/↓` 同时要服务"历史/焦点环/建议"三件事（阶梯 5 的 if 链）；另有一套 `picker-layer`（`/model` 之类的 Surface 菜单） |
| 目标 | 建议列表成为 **Composer 拥有、Router 转发的 Surface**：`↑/↓` 在建议可见时归它，Tab 归它；`picker-layer` 与它共用同一份"列表 + 高亮 + 热键"实现 |

| 风险 | 中。Tab 与 Shift+Tab 在 composer 里还有"插入两空格"的旧语义（`handleChar` 的 `\t` 分支），迁移时要保留 |
| 验证 | `tests/commands.test.mjs`、`tests/picker-*.test.mjs`、新增"建议可见时 ↑/↓ 不翻历史"用例 |

## W-5 · Search Screen（`/find` 有屏）

| 项 | 内容 |
|---|---|
| 现状 | `/find` 是 composer 驱动的：Alt+f/F// 把 `input` 设成 `/find `、`stepSearch` 在 Alt+n/p 上、命中数是一条 `find-feedback` 转写行（`applySearchHits`）；Screen 里只有 `searchRevealed` 一个布尔 |
| 目标 | `ScreenKind` 增加 `search`：自己的字段（复用 setup 的字段机制）、Alt+n/p 是 Screen 级键、结果行可滚动、`/copy` 与（借 Workspace 的）只读选择可用 |
| 成本 | ~350 行（新 Screen + 渲染 + 键位），依赖 W-2（字段与键都要走 Router） |
| 风险 | 中。"Screen 深度 ≤ 1"必须保持（搜索屏不叠在报告屏上，而是替换）；`ScreenKind` 每加一个都要过 `tests/screen-contract.test.mjs` |
| 验证 | screen-contract（每个尺寸/深度/滚动）+ `/find` 现有用例 + 真机探针 |
| 完成判据 | `/find` 在框模式打开 Screen、在行模式仍打印行；Alt+n/p 在两种模式下语义一致 |

## W-6 · Terminal Doctor（终端能力体检屏）

| 项 | 内容 |
|---|---|
| 现状 | 终端能力散在三处：`terminal-caps.ts`（声明面）、`/diag` 的 terminal 行（现状快照）、探测（CPR 往返、glyph 宽度、`unmeasured` 路径）。用户报"某键没用/某符号错位"时，没有一条命令能给出结论 |
| 目标 | `ScreenKind` 增加 `doctor`（或复用 `report` + `report: 'terminal'`）：逐项列出**测到的**、**假定的**、**未测的**（沿用 `docs/terminals.md` 的证据等级），并提供"重跑探测"键（重跑 CPR/宽度/glyph，结果写回同一屏） |
| 成本 | ~250 行；多数是渲染 + 复用现有探测函数 |
| 风险 | 低-中。重跑探测会发 `CSI 6n`，而回复必须**永不**进入字段——这条正是 W-1 Reader 的 `reply` 事件（T-4 覆盖） |
| 验证 | `tests/diag.test.mjs`、`tests/terminal-input.test.mjs`（回复注入）、`tests/glyph-probe-leak.test.mjs` |
| 完成判据 | 一条命令能回答"这台终端：鼠标/SGR/拖拽/括号粘贴/备用屏/OSC52/OSC8/标题/宽度策略分别是测到还是假定" |

## W-7 ·（可选，最后）picker 的 router 统一

`showSessionPicker` 在 TUI 之前跑，自带一套 `TerminalInputGuard` + `escapeBuffer`/`escapeTimer`（G-6/G-9）。
W-1 之后它至少能共用 Reader；彻底统一（共用 Router）留到 W-4/W-5 稳定之后，避免同期动两处最热路径。

## 顺序、门槛与不做的事

| 批次 | 内容 | 门槛 |
|---|---|---|
| 0.8.4-a | W-0 + W-1 + W-2 | 全量测试 + `freeze`（含新 F 计数器）+ 三条真机探针 + `bench` 无退化（**W-0、W-1、W-2 已完成**） |
| P-1 | 探针窗口归属（**已完成 2026-10-14**，见 `docs/checkpoints.md` P-1 节） | 6c 改判**帧级归属**（产品界标，不用 pty chunk）：六项命名检查、chrome 块豁免、整带移动即红；M1–M3 实测红、M4 不误判；0.1.7-rc.1 真机 20/20 |
| 0.8.4-b | W-3a（**已完成 2026-10-14**）→ W-3b | W-3a：G-1/G-2+G-8/G-3 转绿、成对轨迹、M1–M5、四条真机探针（见 `docs/checkpoints.md` W-3a 节）；W-3b：`SURFACE_COMPOSER_KEYS`、Ctrl+L 两份实现、`composerUnit` 拆分 |
| 0.8.5+ | W-4 → W-5 → W-6 →（可选）W-7 | 每项独立发布，各自带自己的探针/用例 |

**不做**（本轮与 0.8.4 都不做）：
- 不改任何键的**默认**语义（默认表原样；只修"合并 read 时丢键"）；
- 不启用 kitty 键盘协议、不启用 focus 上报（`?1004h`）；
- 不实现可从进程内读系统剪贴板（OSC 52 读回终端普遍禁用）；
- 不做 UI 重设计（W-4/W-5/W-6 只加屏与键，不改现有视觉语言）；
- 不动 B2 的八条不变量与七条退役路径，只**新增** F 系列计数器。

## 验收判据（0.8.4 整体）

1. `handleInputText` = Reader → Router → owner，三行能读完；
2. `this.screen` / `this.dialog` 的读取点只剩 Router 与 owner 白名单（freeze 计数为 0）；
3. G-1/2/3/8/10 有一次"红→绿"的用例记录；
4. `npm test` / `freeze` / 三条真机探针 / `bench` 全绿；
5. 默认键位表逐字节未变（`tests/keymap.test.mjs` 原样通过）。
