# 0.8.2-rc.1 发版说明（候选版）

> **这是候选版（RC），不是发布版。** 版本号已就位、材料已备好，但**没有推 tag、没有发布 npm、没有建
> GitHub Release** —— 按 [`release.md`](release.md) 的规则，发版要用户明确要求。
> 上一次发版：**0.8.1**（2026-09-30，`latest` + `next`）。
> 这一版是**架构收尾 + 稳定性**：把 0.8.x 期间分批落地的终端架构（screen / 表示管线 / 工作区区域）
> 冻结下来，并修掉两处**只有全新安装或弱链路才会遇到**的问题。

## 头等事：全新安装**第一次就会出现配置向导**（此前根本不会出现）

0.8.1 及以前，一台**没有任何配置**的机器上装好插件、启动 `dsh --profile tui`，看到的是：
一个空工作区、一行都没有的提示，模型调用必然失败 —— **配置向导永远不会自动出现**。

原因不在向导本身（它是好的），而在触发它的判断：前端拉起后台 Host 时**永远**带上
`--resume=<id>`（连它自己刚生成的那个新 id 也带），而首启判定把 `--resume` 当成"这台机器配置过"，
于是直接跳过了首启流程。

0.8.2 起这条判断只看**凭据存不存在**：没有凭据、环境里也没有 key，就是首启，向导自动打开（Enter 走步骤、
Esc 随时退出），并且工作区会同时留下一行说明告诉你怎么手动重开 `/setup`。**第二次启动不会再出现**。

这同时修掉一个连带问题：向导不再借用 composer 的输入框。0.8.1 里进入向导会**清掉你已经打了一半的草稿**；
现在向导有自己的字段、自己的光标，工作区里的草稿、历史、正在进行的输入一个字都不动。

## 工具卡与输入法：两处"画面串行"的修复

- **工具卡内容含多行代码时不再窜到输入区**。`bash` 卡片的标题就是命令行原文，遇到 heredoc（`<<'PY'`）会带
  着换行进入"一行"——终端因此真的换了行，而这一版之前按绝对行号绘制的帧随后把下面每一行都写错位：卡片内容
  落在输入框和页脚上，甚至两段文字拼在同一行。现在标题行会把换行折成空格，单行裁剪器也不再把换行交给终端。
- **Windows Terminal + 微软输入法：预输入不再在处理中卡片那一行闪烁**。终端把输入法的预输入画在光标处，
  而"写一行"会把光标留在该行末尾；跑一轮时实时区域每 tick 重画又正好在输入框上方，所以光标停在处理中卡片
  上。现在每写完一行就把光标交还输入框，预输入只会出现在它该在的地方。

## 命令提示会自己让位（排队提示除外）

命令的确认（"已复制 412 字"）与警告（命令失败）从此**显示约 6 秒后自动让位**，恢复原来的遥测行；按 Enter
提交仍会立刻清掉。**唯一的例外**是"运行中已提交，将在下个步骤生效"这条：它显示到那条消息**真正被提交**
为止——它是"你有话在排队"的唯一标记，提前消失等于把排队这件事藏起来。

## 弱链路 / SSH：画面更稳，流式不再整屏重画

这一版把 0.8.x 期间逐块落地的渲染架构冻结下来，对**远程、跳板机、弱网**最直接的三条：

- **流式输出不再每个 tick 整屏重画**：正在生成的回复是一个**投影**，不再是往历史里追加行，所以每个
  token 批次只重画它自己那几行。实测（100×20）：一次流式 delta 寻址 **3 行 / 478 字节 / 0 次全屏清屏**。
- **报告不再污染对话记录**：`/status`、`/help`、`/doctor`、`/subagents`、`/diag` 现在是**独立的屏**，
  打开不改变历史窗口位置，翻页只重画正文，Esc 回到你原来的位置，也不会在重连后被重新画出来。
- **断线重接后表示一致**：提问、审批、计划三种卡片从**会话日志**折叠出来，因此掉线重接、换窗口、
  `--resume` 之后读到的状态与当时一致，而不是"重连后多出一张卡"或"状态回到未知"。

## `/clear` 只清可见视图

`/clear` 不删除任何东西：不删会话日志、不动模型上下文、不动计划 artifact。它只是把**可见视图**切到
当前时刻之后（并且用一行提示告诉你这件事）。`/resume` 进来仍然是完整历史。`/find` 只在你**看得见**的
范围里搜索，这一点也在提示里说明。

## 计划与实时处理的抢占关系

计划条（Plan Dock）不再被"处理中"的实时区域盖住：实时区域现在是**自己的行**，而不是画在历史上面。
计划条高度上限为工作区一半，所以它不会把输入框和光标挤出屏幕（中文输入法的预输入串也不会再落到
计划卡上）。终端很矮时计划条按三档降级（完整 / 紧凑 / 极简），不会直接消失。

## 反馈去哪了（"我执行了命令但没有任何提示"）

- 控制面的确认（切主题、切视图、preset 写入…）进**页脚**，显示到下一次输入为止；
- 警告与失败进**身份行**（原来 `目录:` 那一行），不盖住你正在读的内容；
- 只有**会改变历史**的事实才进对话记录。
  页脚挤不下时确认会退到身份行显示，所以再也不会有"执行了但什么都没有"。

## 上游 400：现在会告诉你它是什么

`command-code` 这类思考模式网关偶尔会**成串**拒收请求（实测：一次长会话里 13 个失败轮次中 12 个是这种），
以前你只看到一行原始错误。现在：

- 明确说出**网关拒收的是请求本身、不是你的 key**；
- 指名已知的那一族缺陷（上游 #1780 / #231，思考模式的 reasoning 回传）；
- 给出可操作的两条绕法（该路线 `/effort off`，或换同一网关的 command-code-messages）；
- **不会自动重试** —— 实测这类失败会成串出现（连续 8 轮），重发通常值得，但同一个请求确定性失败时
  自动重试会白花一整段上下文。什么时候重发由你决定。

## 安装 / 升级

```sh
dsh plugin --profile tui add dsh-ssh-tui@0.8.2-rc.1
```

装完退出再启动。`/status` 可确认当前版本；装不上先看 `/doctor`。

## 已知限制

- **Windows / ConPTY 实机尚未人工确认**（本版发布前的必做项）。CI 的 Windows 腿跑的是脚本探针与单元
  套件，**不等于**人工通过：输入法组合、鼠标拖选、宿窗口关闭后重接这些仍要人在真机上走一遍，
  清单见 [`release.md`](release.md)「发布前人工门槛」。
- **拖放探针此前约 1/7 概率误报**（探针自身与自己的 `/status` 重试竞态，不是产品行为）。本版已修，
  并连跑 20 次验证。
- `--resume` 与首启的关系见上文：本版修的是"新机器不显示向导"，不是"resume 不再触发向导"。
- 依赖旧版 inbox 通知（inbox P3）与新协议的命令不在本版范围内。
